# История версий

Подробный журнал изменений Phoenix (новые сверху). Для разработчика: что исправлено, по каким логам и что осталось непроверенным на устройстве.

## Версия 3.9.64
- Встроенные источники белого режима расширены с 2 до 11: добавлены самые стабильные по накопленным данным (AetrisVPN, Prometheus, vlessfo, etoneya, zieng2 lite, StekloVPN, GooseVPN ×2, akres). Новым пользователям не нужно ждать, пока набор соберётся сам.
- Добавлены `docs/BASELINE.md` и `app/src/main/assets/baseline_sources.tsv`: статистика источников и сервисов из реального использования, без токенов и отдельных серверов.

- **Интерфейс:** список серверов убран с главного экрана. Теперь отдельное окно «Серверы» (кнопка вверху): все показатели, 9 сортировок с разворотом направления, фильтры по живым, проверенным, стабильным, протоколу и стране, поиск. Логика в `ServerTable.kt`, покрыта тестами.
- **Интерфейс:** главный экран прокручивается целиком; убраны дубли: перепроверка серверов только в «Серверах», кнопки разрешений для фона только в «Фоновая работа (прошивка)».

- **Языки:** интерфейс и уведомления переведены на English, Українська, Türkçe, Español, 中文, فارسی, العربية (415 строк). Язык берётся из системы; поддержка письма справа налево (`supportsRtl`), `locales_config.xml` для выбора языка приложения в Android 13+. Тексты в коде обёрнуты в `tr("…")` (`I18n.kt`), словари в `assets/i18n/`, инструменты в `tools/i18n/`. Нет перевода — показывается русский. Журнал не переводится.

- Первый запуск без истории: сбор откладывается на 90 с, перепроверка идёт втрое меньшим числом параллельных проверок (защита от «приложение не отвечает»).
- Импорт бэкапа: лимит поднят до 40 МБ (копии с историей весят 7–10 МБ).
- Исправлен тест словарей переводов; CI скачивает libv2ray.aar сам.

## Версия 3.9.57
Gemini и NotebookLM не работали на 3.9.55, хотя проверка находила серверы (журнал 07.11: страница Gemini через Финляндию открывалась нормально).
Вероятная причина (по коду маршрутов, на устройстве не проверена): сервис шёл через свой сервер, а вход в аккаунт и служебные узлы Google (accounts.google.com, googleapis.com, Play Services) через основной — Google видел две страны для одного аккаунта.

- XrayConfig: правила по приложению теперь стоят раньше правил по доменам.
- Проверка Gemini/AI Studio дополнительно смотрит NotebookLM через тот же сервер как «датчик» отношения Google к его адресу.

## Версия 3.9.55
По журналу 3.9.48 (смена режима на мобильной сети занимала до 10 мин):

В журнале строки `DIAG:` (код, время, цепочка переходов, признак заглушки региона). Запускается из проверки связи (`diagGoogle`), на другие приложения не влияет.

## Версия 3.9.49 (versionCode 61)
По повторному аудиту 3.9.48 (подтверждено журналом 05.11 11:01: после «перепроверка прервана» шли «SVC: … рабочих 0» и «BYPASS: напрямую не открылось ничего»):
- **Прерванная перепроверка** (нет интернета, смена сети или режима, 200 проверок без живых) больше не запускает проверку сервисов, обхода и смену приоритетов, а при отсутствии интернета — и перепроверку целей. Ложные «не работает» не записываются.
- **История серверов:** пачка отказов TCP без единого ответа (≥20) или недавно подтверждённое «нет интернета» не записываются как отрицательный опыт конфигов.
- **«Нет интернета» при поиске:** кроме 120 отказавших конфигов нужно не меньше 40 разных узлов (несколько конфигов одного сервера не складываются).
- **Проверка связи (HEALTH):** если ядро перезапускали, пока шла проверка, отрицательный результат отбрасывается (раньше защита смотрела только занятость блокировки в начале).
- **Порядок для Chrome и целей без своего сервиса:** учитываются только свежие (до 3 дней) результаты по тому же адресу сервера.
- Тесты: `Release3949Test`. Харнесс: ALL OK (391).

- **Сначала задержка, потом точнее.** Живые, найденные поиском, запоминаются; в рейтинге проверенные живые (за последние сутки) идут первыми. Точные проверки (сервисы, скорость) делаются позже и только для найденных. Фоновая проверка раз в 6 часов, если свежих живых меньше 20, сначала делает такой же широкий поиск по всей очереди (до 2 минут), а не проверяет только «лучшие по рейтингу», которые могут быть мёртвыми.
- **Первая проверка связи через 4 секунды после подключения** (раньше через 25).
- **Смена режима реже «застревает».** Тип блокировок определяется ещё раз каждые 5 минут, пока экраном пользуются (десять маленьких запросов), сразу при пропадании связи и при смене сети. Если первое определение показало другой тип, второе делается через 3 секунды, а не при следующем событии (режим меняется после двух одинаковых подряд). Раньше в чёрных списках мог остаться ярлык, а работал сервер белых.
- **Метки в названиях.** Конфиги, которые сама подписка помечает «Белые списки»/«whitelist» (или «Чёрные списки»), в чужом режиме пробуются после остальных (не исключаются).
- **Низкая скорость.** Кандидатов ищет тот же быстрый поиск, а скорость мерится маленьким файлом (до 400 КБ) через отдельное ядро, рабочий туннель при этом не трогается.
- **Сбор конфигов, когда напрямую закрыто.** Если источник напрямую не открылся (обрыв, а не ответ сервера) и VPN включён, загрузка повторяется через локальный прокси VPN (приложение само идёт мимо VPN, поэтому при белых списках GitHub напрямую недоступен).


## Версия 3.6
- **Режимы и сервер.** Последнее подключение теперь хранится отдельно для каждого режима. В чёрных списках больше не всплывает сервер из белых: при смене режима (вручную или автоопределением) работающий VPN сам переходит на сервер нового режима. Если у режима нет своих конфигов (у чёрных списков по умолчанию не заданы источники), берётся сервер другого режима, и на главной карточке это написано.
- **Низкая скорость.** Пока телефоном пользуются, раз в 45 с по счётчику трафика приложения видно, идёт ли поток; если потока мало, делается один замер до 400 КБ. После двух медленных подряд (порог 0.3 / 0.5 / 1 / 2 Мбит/с, по умолчанию 0.5) пробуются до 3 других серверов, берётся заметно более быстрый, иначе остаётся прежний. Не чаще раза в 5 минут и 4 раз в час. Без активной работы ничего не качается. Включается в Настройки → Подключение.
- **Опыт конфигов.** Приложение запоминает (без дополнительных проверок, только из уже идущих), какой конфиг в какой сети работал: Wi-Fi или конкретный оператор, отдельно для каждого режима. Конфиги, подводившие в этой сети, уходят в конец выбора; в карточке конфига строка «Где работал: Wi-Fi 12✓/1✗ · моб. мтс 0✓/5✗». Записи старше 60 дней забываются.
- **Цели.** «общее» переименовано в «как везде». Для каждого приложения есть адрес проверки (известный, а если неизвестен — общий «сервер работает»), его можно поменять кнопкой «Адрес». Известных приложений стало около 45. Если ядро не принимает ответ сайта (Claude, ChatGPT отвечают 403 защиты), цель подтверждается мягкой проверкой через SOCKS: любой HTTP-ответ 200–499 значит, что сервер дотянулся.
- **Чёрные списки: обход не заблокированного в РФ.** Steam, GitHub, Wikipedia, Microsoft, Apple, Amazon, AliExpress, Zoom, Twitch и подобное идут напрямую (Настройки → Обход VPN). По умолчанию включено только в чёрных списках, в белых выключено; Telegram, YouTube, Instagram, Discord, ChatGPT, Claude остаются в VPN.
- **Экспорт и импорт** (Настройки → Экспорт и импорт): текстовый файл с настройками и, по каждому режиму, целями (без ключей серверов), обходом, своими источниками, чёрным списком источников, выбранными сервисами и опытом конфигов. Импорт ничего не стирает: списки объединяются, чёрный список только пополняется.
- **Исправления из журнала.** Ключ Reality `pbk` с «+» читался с пробелом («invalid password») — теперь «+» сохраняется. Серия из нескольких подключений подряд сведена к одному (повторная команда в первые 8 секунд игнорируется, автоподключение не чаще раза в 20 секунд). Если фоновая проверка целей прервана системой («Job was cancelled»), она повторяется через 10 минут. После неудачного перебора запасных серверов возвращается прежний сервер, а следующая попытка идёт с растущей паузой (1, 2, 4… до 10 минут).

## Версия 3.1
- **Проверки быстрее и честнее.** Перед запуском ядра сервер проверяется обычным TCP-соединением (2–3 с вместо ожидания ~10 с внутри ядра), адрес сервера-домена передаётся ядру заранее в `dns.hosts` (как в v2rayNG — иначе у ядра нет способа найти IP сервера), параллельно проверяются 6 конфигов.
- **Запасные на разных серверах.** Конфиги с одним хостом и разными протоколами считаются одним сервером: в запасные и в перебор при падении берётся лучший из них (больше работающих сервисов → скорость → задержка). На главном экране — «Запасных проверено: N».
- **Вариант А/Б выбирается сам** (режим «Само выбирает», по умолчанию): сайты — А; приложение — А, если ядро умеет узнавать приложение по соединению, иначе Б (при выданном доступе к данным об использовании).
- **Wi-Fi определяется по настоящей сети под VPN** (раньше «активной» была сама VPN-сеть).
- **Источники для белых и чёрных списков** редактируются на одной странице с переключателем режима (общий список, свои ссылки, чёрный список, аудит) независимо от включённого режима; у белых списков можно указать свой общий список вместо встроенного.
- **Проверка «братьев».** Конфиги с одного сервера проверяются по очереди, начиная с самого приоритетного протокола; ответил один — остальные пропускаются («не проверялся»), не ответил — берётся следующий. Лимит «15 лучших» теперь считается в серверах, а не в конфигах.

## Версия 3.0
**Экраны.** Главный экран — VPN (состояние, крупная кнопка «Подключить/Отключить», лучший конфиг с задержкой и скоростью) и список конфигов. Всё остальное — в «⚙ Настройки»: режим блокировок, приложения и сайты, обход VPN и проверка сервисов, подключение, автосбор, источники, отчёт.

**Плитка в шторке.** «Phoenix VPN» включает/выключает VPN. Добавить: Настройки → Подключение → «Добавить плитку» (Android 13+), либо вручную через значок карандаша в шторке. Первый раз приложение попросит системное разрешение на VPN.

**Переподключение.** Каждые ~25 с (пока экран включён) и при смене сети/включении экрана проверяется, ходит ли трафик через туннель. После трёх неудач перебираются запасные конфиги по рейтингу (стабильные дни → Мбит/с → задержка).

**Приложения и сайты с запасными серверами.** Для каждой цели держится до 3 проверенных серверов (перепроверка раз в 6 часов и после каждого сбора). Вариант А — только это приложение/сайт идёт через свой сервер (правила по UID приложения/домену в ядре); вариант Б — при открытии приложения весь VPN переключается на его сервер (нужен «Доступ к данным об использовании», пауза 2 минуты между переключениями). Выбирается общий вариант и можно переопределить для каждого приложения.

**Обход.** Российские приложения (43 пакета) и российские домены идут напрямую по умолчанию; свои приложения и сайты добавляются в «Обход VPN».

**Режим.** Тип блокировок определяется сам (6 зарубежных и 4 российских адреса напрямую; режим меняется после двух одинаковых результатов подряд, при смене сети — не чаще раза в 30 с). Данные у режимов раздельные; ночной сбор идёт для каждого режима, у которого есть источники.

**Одинаковые конфиги** определяются по протоколу + имени (адрес может меняться — история остаётся; если адрес сменился, старая проверка помечается устаревшей).

**Задержка и скорость.** Задержка — реальный HTTPS-запрос через конфиг. Скорость — загрузка через временный локальный SOCKS (до 6 с / 8 МБ), по умолчанию только по Wi-Fi.

**Ядро.** Нужен свежий libv2ray.aar из AndroidLibXrayLite (релизы вида 26.x; проверено на 26.10.10): https://github.com/2dust/AndroidLibXrayLite/releases/latest Старое ядро (Lib v30) не поддерживается.
