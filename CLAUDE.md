# Phoenix — правила работы

Android-клиент VPN (Xray) и сборщик конфигов. Kotlin, Compose Material3, пакет `com.phoenix.app`. Исходники: `app/src/main/java/com/phoenix/app`.

## Сначала
1. Открой `ARCHITECTURE.md`: там «вопрос → кто решает → файл». Новое правило добавляй в существующего «решающего», а не заводи второго (так появлялись `NetFlap` рядом с `HealthGate`).
2. Ищи по именам функций и объектов, не по номерам строк.
3. Большие файлы целиком не читай: `PhoenixVpn.kt`, `MainViewModel.kt`, `ServiceFailover.kt`. Читай нужную функцию.
4. Не открывай `app/src/main/res/values-*/strings.xml`, `tools/i18n/keys.txt`, `CHANGELOG.md` целиком и `docs/HANDOFF.md` (устарел, версия 3.9.54). Журналы читай через `tools/logscan`, затем нужное окно по времени.

## Как проверять (Gradle в песочнице не собирается)
```
bash tools/kt-harness/run.sh     # тесты чистых файлов (список в tools/kt-harness/pure.txt, тесты в tests.txt)
bash tools/kt-harness/syn.sh     # синтаксис всех .kt; важно «syntax: 0» (общее число unresolved ~7000 — норма)
python3 tools/i18n/check.py      # переводы: «отсутствуют: 0»
bash tools/check-docs.sh         # карта ARCHITECTURE.md против кода
```
Новый чистый файл (без Android) добавь в `tools/kt-harness/pure.txt`. Сборку (`./gradlew assembleDebug`) и проверку на телефоне делает владелец. Всегда пиши «не проверено на устройстве».

## Правила правок
- Разбивка файлов: код только переезжает, исправления отдельным шагом. Закрытые члены, нужные другому файлу, делай `internal`.
- Логика без Android — в чистые объекты с тестами (как `NetState`, `HealthDecision`, `OutageEpisode`), состояние службы туда же.
- Строки интерфейса: `tr("...")` и русский текст в коде; переводы добавляй через `tools/i18n/addkeys.py` (JSON), файлы переводов руками не правь.
- Не добавляй список адресов сервисов в новое место: каталог сервисов один (см. ARCHITECTURE.md).
- Не клади в репозиторий и в отчёты ключи подписок, пароли, токены, IP серверов (только страна).

## «Сделано» для каждой правки
- Тесты зелёные, `syntax: 0`, i18n без пропусков.
- Запись в `CHANGELOG.md` (кратко, до 5 строк на пункт; причина и журнал, из которого взято).
- Если появился новый «кто решает» — строка в `ARCHITECTURE.md`.
- Тест на сценарий из журнала, если правка закрывает найденную в журнале проблему.

## Версии и релиз
- Перед выпуском пройти `docs/RELEASE_CHECKLIST.md`: пункты с пометкой (Claude Code) — свои, остальные делает разработчик; автоматическая часть — `bash tools/release-check.sh`. К каждому выпуску факты бегущей строки пересматриваются и добавляются 1–3 новых (`Facts.REVIEWED_FOR`).
- Текущая версия 3.9.68 (versionCode 82), выпуск вручную по RELEASING.md. Новые записи — в раздел «В работе (после 3.9.68)» в CHANGELOG.md.
- Коммиты и релиз делает владелец, после проверки на телефоне. Не коммитить без просьбы. Подпись debug-ключом, выпуск вручную (`RELEASING.md`).
