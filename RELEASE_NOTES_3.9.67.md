# Phoenix 3.9.67

Не проверено на устройстве до выпуска; журнал после установки поможет подтвердить правки.


### По разбору Opus (журнал 20.11), порция 1: счётчики и безопасные правки
- **Счётчик «не открылись 0».** В поиске провалы TCP после первого открытого порта не считались (`ServerSearch`): в журнале «не открылись 0» при ~1500 отброшенных. Считаются всегда. Время пробы теперь разбито на живые и мёртвые (журнал: «живые N мс ×K, мёртвые M мс ×L»).
- **Отсев по адресу с учётом транспорта.** Три провала подряд на одном `хост:порт` больше не выбрасывают остальные конфиги адреса: ключ включает SNI/Host, путь, тип и безопасность (учётные данные не входят). За общим CDN-адресом живые не теряются.
- **Ограничитель нагрузки не винит сам поиск.** Поиск при обрыве начался из-за сбоя связи, а ограничитель считал его виновником и поднимал уровень сети (срочный поиск шёл на половине проб весь день). Теперь передаётся время первого сбоя. Уровень сети также снижается сам через 2 часа без новых сбоев.
- **Перерыв считается от первой неудачи проверки связи**, а не от начала смены сервера или режима (раньше 17 с и ~47 с не учитывались).
- **«Не работает» для одного сайта убирает сервер только у целей этого сайта**, а не у всех (NotebookLM больше не вычёркивает общий сервер у Telegram и Discord). Список целей берётся свежий из файла. В журнале строка «VETO: сервер убран у целей этого сайта: …».
- **Этап «сначала подходящие» сужен**: не больше 40 серверов, и без проверяемого сервиса «подходящими» не считаются все непроверенные серверы (было «1521 из 1677», до 180 с вместо 120 с). Если первый этап закончился на «нет интернета», второй не запускается.
- **Лимит мобильного трафика действует и на поиск целей**: после исчерпания суточного лимита поиск живых, глубокий и последний поиск для целей не идут (раньше шёл поиск 585 серверов).
- **Подбор целей после пересборки туннеля запускается через 45 с**, а не мгновенно (система снимала его с причиной 7, повтор шёл через 10 минут).
- **Защита от «шторма смен»**: если за 10 минут было больше 3 автосмен сервера, следующая откладывается на 20 с за каждую лишнюю (не больше 90 с) — пачки смен рвали связь. В журнале строка «за 10 минут уже N автосмен».
- **Проверка нового сервера после переключения короче** (0,9 + 0,8 с вместо 1,2 + 1,0 с): плохой кандидат отсеивается быстрее.
- **Опыт по Telegram (T3), только журнал:** при проверке Telegram в подборе целей рядом со страницей web.telegram.org пробуется прямой ответ дата-центра (149.154.167.50). Строка «TG-DC: … страница …, дата-центр …». На итог ✓/✗ не влияет: по журналу решим, можно ли доверять такой проверке.
- **Ошибка сертификата не считается «закрыто»** (находка C3): если сервер дотянулся до сайта, но сертификат не принят (банки, Microsoft), мягкая проверка засчитывает сайт как «отвечает» (≈), а не как закрытый.
- **Сервисы берутся из целей.** Встроенные TG/QW/CL/YT/ST и свои сервисы больше не проверяются отдельно: колонка = цель (адрес проверки цели). Подпись — сокращение названия: части по пробелам и заглавным буквам, первые буквы первых двух (YouTube → YT, YouShorts → YS), одно слово — две буквы (Steam → ST); совпавшие получают три буквы, потом цифру. Цели с одним адресом проверки делят колонку. Старые результаты TG/QW/CL/YT/ST подтягиваются по совпадающему адресу. Без целей колонок нет. На главном экране не больше двух рядов по семь колонок, остальные — только в окне «Сменить сервер» (там все, по семь в ряд). Страница «Проверяемые сервисы» теперь только показывает список.
- **Полоса сервисов на главной** показывает сокращения целей (YT ✓, ST ≈…), а не id вроде «APP:com.anthropic.claude», не больше двух рядов по семь.
- **Сокращения целей узнаваемее:** для популярных приложений и сайтов — привычные коды (Telegram → TG, Discord → DC, WhatsApp → WA, ChatGPT → GPT, Gemini → GM, Gmail → GML, Grok → GK, DeepSeek → DS, Qwen → QW, Steam → ST, YouTube → YT и ещё ~90 названий). Для остальных: несколько слов — первые буквы первых двух (YouShorts → YS), одно слово — первая буква и следующая согласная (Starlink → ST). Совпавшие получают три буквы, потом цифру.
- **Смена режима не ждёт самый медленный вариант.** Быстрые варианты проверяются параллельно, но теперь ждём только первого ответившего и 1,5 с для остальных (не больше 15 с). Раньше предпроверка ждала все четыре (журнал 20.11: 34 с, потом перезапуск рвал связь).
- **Проверка сервисов быстрее** (журнал 21.11: 12 сервисов у 30 серверов — 425 с, ~14 с на сервер): сервисы одного сервера проверяются по 3 одновременно, на мобильной сети и на слабых телефонах — по одному, как раньше.
- **Вердикт региона «2 из 3»** (находка C1/T4): страница Google-сервисов через один и тот же сервер отвечала по-разному от запроса к запросу (Notebook и Gemini через GB то «✓», то «✗»; проверка целей и таблица сервисов расходились). Теперь нужны два одинаковых ответа, третье чтение — только при расхождении; не набралось двух — «≈», а не уверенное «✓» или «✗». Мёртвые серверы читаются один раз. Цена: лишнее чтение страницы только у сервисов с проверкой региона.
- **Журнал: «живых по источникам».** После пересчёта приоритетов добавлена строка «PRIO: живых по источникам (лучшие 8 из N): хост/владелец 19% (12/63) · …». Ключи подписок и длинные токены в адресах в журнал не попадают (только хост и первая часть пути).
- **Сбой связи при «прыгающей» сети не вешается на сервер** (журнал 20.11: Wi-Fi ↔ мобильная каждые 3–8 минут, Chicago «сломался» трижды): пока сеть недавно меняла тип несколько раз подряд (до 2 минут после последней смены), проверка связи не засчитывает сервер неработающим и не запускает перебор. В журнале строка «сеть недавно меняла тип…».

### Журнал 20.11 (мобильная сеть, белые списки)
- «Связи не было 1200 с»: после неудачного поиска сервера перерыв оставался открытым до следующей смены сервера, хотя проверки здоровья несколько раз показывали «восстановилась» (сервер «TgOnly» пропускает почти только Telegram, связь прыгала). Теперь перерыв закрывается, когда связь вернулась, и учитывается отдельной строкой «сбой связи».
- Строка «Лимит фоновых проверок по мобильной сети исчерпан» писалась каждую минуту (десятки одинаковых строк в журнале). Теперь не чаще раза в 30 минут.
