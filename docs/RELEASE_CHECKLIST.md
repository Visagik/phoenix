# Обязательный список перед выпуском

Проходится при каждом выпуске, по порядку. Пометка в скобках — кто делает: (Claude Code), (разработчик) или (скрипт: `tools/release-check.sh`, с флагом `--final` — ещё подпись и состав репозитория).
Версия X — выпускаемая (например, 3.9.68). Версия и код меняются только в `app/build.gradle.kts`.

## А. Что изменилось
- [ ] CHANGELOG: всё из «В работе» перенесено в «## Версия X (дата)», разложено по темам; «В работе» пустой; в записях этой версии нет чужих номеров версий («-dev», будущие). (Claude Code; пустоту «В работе» проверяет скрипт)
- [ ] Список изменений считается от ПОСЛЕДНЕГО ПУБЛИЧНОГО выпуска (`gh release list`), а не от предыдущей секции CHANGELOG: между ними могли быть невыпущенные версии. (Claude Code по номеру, который назовёт разработчик)

## Б. Для пользователей
- [ ] `RELEASE_NOTES_X.md`: простыми словами, по группам, без внутренних номеров задач и имён файлов, ничего сверх CHANGELOG. Файл есть — проверяет скрипт. (Claude Code)
- [ ] «Что нового» (`WhatsNew.kt`): запись X, 3–8 пунктов, всё заметное пользователю, перевод на 7 языков (`tools/i18n`). Запись есть — проверяет скрипт. (Claude Code)
- [ ] Факты бегущей строки (`Facts.kt`) — традиция каждого выпуска: каждый факт сверен с кодом (числа — с константами), устаревшие исправлены, 1–3 новых про новое в этой версии, перевод на 7 языков, `Facts.REVIEWED_FOR = "X"`. Совпадение `REVIEWED_FOR` с версией проверяет скрипт. (Claude Code)
- [ ] «Ещё → Фишки» (`TipsPage.kt`): нужна ли карточка для новой возможности. (Claude Code предлагает, решает разработчик)
- [ ] Подсказки у новых и изменённых настроек совпадают с поведением (числа — с константами). (Claude Code)
- [ ] Обучение (первый запуск) не описывает то, чего уже нет. (Claude Code)
- [ ] `docs/screenshots`: если менялся вид экрана из скриншотов — пометить к замене. (разработчик)

## В. Документы
- [ ] README (если описано поведение), `ARCHITECTURE.md` (`tools/check-docs.sh` — скрипт проверяет), `docs/HANDOFF.md` и `CLAUDE.md` (строка версии), `TODO.md` (раздел релиза → следующая версия), `THIRD_PARTY.md` (новые библиотеки), `RELEASING.md` (команды на X). (Claude Code)

## Г. Версия и проверки
- [ ] `versionCode` и `versionName` подняты; в `versionName` нет «-dev». (скрипт)
- [ ] `tools/kt-harness/run.sh`, `syn.sh`, `tools/i18n/check.py`, `tools/check-docs.sh`, `tools/release-check.sh`. (Claude Code; `release-check.sh` сам запускает i18n и check-docs)
- [ ] `./gradlew :app:assembleFullDebug :app:lintFullDebug` без ошибок. Если выпускается Lite — ещё `:app:lintLiteDebug`. (разработчик)

## Д. Подпись и файлы (разработчик)
- [ ] Отпечаток ключа машины = отпечаток прошлого релиза: `apksigner verify --print-certs <apk прошлого релиза> | grep SHA-256` и `keytool -list -v -keystore ~/.android/debug.keystore -storepass android | grep SHA256`.
- [ ] В `RELEASE_NOTES_X.md` строка «Подпись: <SHA-256>» (можно с двоеточиями). (скрипт с `--final`)
- [ ] В релизе full ровно один APK, в имени файла нет «lite»; Lite — только отдельным предрелизом (`RELEASING.md`).
- [ ] Копия `~/.android/debug.keystore` вне проекта актуальна.
- [ ] `git status` без APK, ключей и `.so` из Lite. (скрипт с `--final` проверяет `git ls-files`)

## Е. Телефон, 15 минут (разработчик)
- [ ] Установка поверх прошлой версии: версия и настройки на месте.
- [ ] Подключение; «Сменить сервер» и «Не работает»; Wi-Fi ↔ мобильная; выкл./вкл.
- [ ] Окно «Что нового» показалось один раз.
- [ ] Бегущая строка показывает новые факты и не вылезает за край.
- [ ] Диагностика сохраняет журнал.

## Ж. После публикации (разработчик)
- [ ] Play Защита («Проверить»): предупреждений нет.
- [ ] «Ещё → Обновления»: пишет, что стоит последняя версия, на подпись не ругается.
- [ ] Файл, скачанный со страницы релиза, даёт тот же `sha256sum`, что собранный.
- [ ] Журнал за сутки — по списку «что проверить после обновления» из задания на выпуск.
